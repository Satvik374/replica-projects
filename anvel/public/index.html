The parts people actually use

  • Chat and preview, side by side. One column for the request, one for the result. Files touched are listed on the answer.
  • A real editor. File tree, tabs, and Ctrl+S. Hand edits cost no usage and land in the next preview.
  • Version history. Every turn is a snapshot. Rename it, bookmark it, restore it.
  • Publish, unpublish, update. A live site is a copy, not a pointer — so nothing goes public by accident.

What this is, plainly

Anvel is a study rebuild of the prompt-to-app loop, written from scratch. It is not an AI model and it will not pretend to be one: the agent works from a set of app blueprints and a fixed vocabulary of edits.

It really does build

Ten blueprints, real state, real interactions, three files each. Previews are sandboxed iframes, so nothing generated can touch your account.

It says no

Ask for something outside its moves and it explains that, rather than returning a half-built guess. Code view is there for the rest.

No secrets, no services

Accounts, projects, versions and publishing all run in one Worker with SQLite. No third-party keys are needed to run it.

What this is

Anvel is a clean-room rebuild of a prompt-to-app editor: same job, own name, own palette, own code.

  • Real files. Every build is index.html, styles.css and app.js, editable in Code view.
  • Your choice of agent. A deterministic local agent with ten blueprints works with no key at all; add an OpenAI-compatible endpoint in Settings and a model writes the files instead.
  • Sandboxed previews. Generated code runs in an opaque origin, so it cannot read your session.
  • Nothing borrowed. No original markup, copy, logos, fonts or endpoints. Layout conventions only.
